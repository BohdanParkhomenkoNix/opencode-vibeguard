# Факты opencode V2 (2.0.26) для порта vibeguard

Снято одноразовым зондом на реальном `opencode run --standalone --print-logs --auto` в изолированном `HOME`/`XDG_*` против мока (`test/helpers/mock-provider.js`). Зонд не коммитится. Доказательства взяты из логов зонда и тела запросов мока; значений секретов здесь нет.

## Rulings

- R1. Плагин в `plugins` задаётся директорией (с `package.json`: `main`/`exports`), не файлом. Путь к файлу даёт `WARN configured plugin path must be a directory target=…/index.js`, плагин не грузится. Работают три формы: абсолютный путь директории, `file:///…/dir`, `file:///…/dir/`. Поэтому `PLUGIN_ENTRY` в `test/helpers/opencode.js` — `file://` URL корня репозитория (`file:///…/opencode-vibeguard`), а не `src/index.js`; точку входа выбирает `package.json` (`exports: ./src/index.js`). Поправка: для локальной директории точку входа выбирает не `exports` — см. R1a.
- R1a (поправка, найдена в Задаче 11). Для локальной директории V2 резолвит `<dir>/server`, затем `<dir>/index` и игнорирует `main`/`exports` из `package.json` (по `package.json` резолвятся только пакеты по имени). Поэтому в корне репозитория лежит `index.js`, реэкспортирующий `src/index.js`; без него плагин молча не грузится.
- R2. F2 «да» и F3 «да»: оба пути блокировки работают, стоп-условие плана не сработало. Страж в `http.request` перекрывает все запросы, включая `title`.
- R3. Изоляция через `HOME` + `XDG_CONFIG_HOME/DATA/CACHE/STATE` достаточна; других переменных не нужно. Сервис OC и реальный `~/.config/opencode` не затрагиваются (`--standalone`).

## F1–F11

- F1. Изоляция работает. В stderr (`--print-logs`) нет `SuperPowersLite`, `shadow-context`, `superpowers`; конфиг-директория в логах `watcher subscribe path=<tmp>/home/.config/opencode`. Проверяет и `test/e2e/smoke.test.js` (`doesNotMatch(stderr, /SuperPowersLite|shadow-context/)`). Строк `loading plugin` runtime не пишет вообще (ни для глобальных, ни для подключённого зонда); факт загрузки плагина виден по его `console.error`.
- F2. `throw` в `context` прерывает запрос. Прогон (b): мок получил только запрос `title` (`system,user`, без `tools`), основного запроса с `tools` нет. Код выхода 1, stdout пуст, stderr: `level=ERROR … message="Failed to drain Session" cause="Error: vgprobe: blocked in context …"` и строка `Error: vgprobe: blocked in context`. Хук `title` отрабатывает отдельно: запрос `title` ушёл к мок-провайдеру, потому что `context` его не покрывает; хук `title` должен прятать секреты сам.
- F3. `throw` в `http.request` прерывает запрос. Прогон (c): `mock.requests.length === 0`, в том числе нет запроса `title`. Код выхода 1, stderr: `Failed to drain Session … Error: vgprobe: blocked in http.request`. Событие `http.request` имеет `kind`: `title`, `primary`, `compaction` (по одному вызову на каждый исходящий запрос).
- F4. Форма данных хуков `context`/`compaction` (`title` — то же без `agent`/`tools`, и сообщения без `id`/`metadata`):
  - ключи события: `sessionID, model, system, messages, options, agent, tools`;
  - `system`: массив `{type:"text", text}` (4 элемента в основном запросе: харнесс, «Your Model», каталог Code Mode, окружение; 1 в `title`);
  - `messages`: массив экземпляров класса (`constructor.name === "ri"`, минифицированное имя; прототип содержит только `constructor`; собственные ключи `id, role, content, metadata`); `content` — массив обычных `Object`-частей (`partCtor === "Object"`);
  - части: `text {type,text}`; `reasoning {type,text,providerMetadata}`; `tool-call {type,id,name,input(объект),providerExecuted,providerMetadata}`; `tool-result {type,id,name,namespace,result,providerExecuted,cache,metadata,providerMetadata}`;
  - `tool-result.result` бывает трёх видов: `{type:"text", value:string}`, `{type:"content", value:[{type:"text",text},…]}` (shell: вывод и `Exited with code N` отдельными частями), `{type:"error", value:{error:{type,message}, content:[]}}`;
  - роли: `user`, `assistant`, `tool`;
  - ничего не заморожено (`Object.isFrozen` — false для события, `messages`, сообщения, части, `system`, элемента `system`);
  - правка на месте (`part.text = …`, `system[i].text = …`) попадает в запрос; присваивание `e.messages = plainClone` и `e.system = plainClone` тоже (потеря класса не мешает). В провайдера уходит `assistant.reasoning_content`, `tool_calls[].function.arguments` (JSON-строка из `input`), `tool.content` (строка из `result`), всё после правок хука.
- F5. Субагент: имя инструмента `subagent` (в `body.tools` и в `event.tool` у `execute.before`). Обязательные аргументы: `agent`, `description`, `prompt`; необязательные: `model`, `sessionID` (`^ses`), `background`. Значения `agent`: `explore`, `general`. Дочерняя сессия: свой `context` и `http.request` (kind `primary`), свои `execute.before`; первое сообщение ребёнка — `You are a subagent spawned by another session.\n<prompt>`; у ребёнка в `tools` 10 инструментов (у родителя 12). Результат возвращается родителю как `tool`-сообщение `<subagent sessionID="ses_…" state="completed">…</subagent>`.
- F6. Compaction: хук `compaction` с теми же ключами, что `context` (`limit`/`usage` в событии нет). Запрос идёт с `http.request kind="compaction"`, с теми же 12 `tools`, что у основного. Тело отличает последнее `user`-сообщение, начинающееся с `You MUST summarize the conversation above into a structured summary`, с разделами `## Objective`, `## Requirements`, `## Decisions`, `## Work State`, `## Next Move`, `## Relevant Files`, `## Important Context`. Если ответ мока не содержит этих заголовков, OC делает повторный запрос (`The previous response did not fill in the required summary template. Do not call tools. …`), затем падает: `Session.StepFailedError: Compaction summary did not match the required template`, код 1. Мок для e2e compaction должен отдавать текст с этими заголовками. Как вызвать: `--session` с id из F7 и мок с `usage.prompt_tokens`, близким к лимиту: `contextLimit: 20000` + `prompt_tokens: 19000` — compaction срабатывает перед вторым запросом второго прогона той же сессии; `16500` и `100` — нет. `contextLimit: 3000` (меньше `output: 4096`) вызывает compaction сразу, до основного запроса первого прогона. Хук `generate` не сработал ни в одном сценарии.
- F7. `--session` принимает только id вида `ses…`: `vgprobe-plain` отвергнут (`schema rejection … Expected a string starting with "ses"`, код 1, ни одного запроса); `ses_vgprobe<время>` на новом id принят, сессия создаётся (`GET /api/session/<id> 404`, затем код 0).
- F8. `websearch` есть в `body.tools` у локального провайдера (12 инструментов: `edit, glob, grep, question, read, shell, skill, subagent, webfetch, websearch, write, execute`; `parameters.required = ["query"]`). - F9. Код выхода `opencode run` при `throw` в хуке — 1 (F2, F3, F6); stdout пуст.
