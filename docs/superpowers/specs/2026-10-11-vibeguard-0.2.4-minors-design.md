## A. Leaks

### A1 (E6, E3) — rule pass learns from views before it masks the raw text

Today `rulePass` (src/messages.js) runs the rules on each escaped view only to register values,
then runs them on the raw gap. A context-free custom rule whose class includes `/` (for example
`[A-Za-z0-9/]{20,}`) matches only the part after `\/` in a PHP-escaped value `abc\/def…`. That
suffix becomes a placeholder, so the full escaped form no longer exists when `knownPass` runs, and
the prefix `abc\/` reaches the provider (E6). Values seen only in a view are also registered when
no form of them is in the text, using `max_mappings` slots (E3).

New order for each gap between existing placeholders:

1. Run the rules on every escaped view of the gap, collecting `{ original, category }` without
   registering anything.
2. Keep a candidate only if the gap contains the original or one of `escapedForms(original)` (E3).
3. Register each kept candidate (`session.getOrCreatePlaceholder`) and replace every occurrence of
   the original and its forms in the gap with the placeholder, longest needle first. A placeholder
   restores exactly the bytes it replaced: a form that the rules already match whole in the raw
   gap (for example a PEM whose newlines are the two characters `\n` inside JSON) keeps its own
   mapping, as in 0.2.3. Only a form the raw rules would split (the E6 case) takes the decoded
   value's placeholder.
4. Run the rules on the text between placeholders of the result, as today.

A value decoded by a view whose spelling in the text is none of its forms (for example ASCII
spelled as `a`) is not registered. The guard still finds it in the view and blocks, exactly as
in 0.2.3, where the registered value could not be replaced either.

Tests: the E6 case (custom rule with `/`, PHP-escaped value, nothing of the value left in the
output); the E3 case (view-only value is not registered, `knownEntries()` unchanged); the existing
notebook / JSON-in-JSON cases still pass; a JSON-escaped PEM in `read` output (`builtin:
["private_key"]`) round-trips: `restoreText(masked) === input`.

### A2 (V44) — README

The Limits section gains one line: opencode's own local logs and session storage keep plaintext;
vibeguard only controls what is sent to the provider.

The Limits section also says: a placeholder restores the exact text it replaced, so a secret
copied into another format (for example a JSON-escaped PEM written to a `.pem` file) keeps the
escaping it had where it was read; move secrets between formats with a command on the file
(`jq -r .private_key sa.json > key.pem`), not through the model.

## B. Key file and error messages

All in fail-closed paths; no behaviour change for a healthy setup.

- **B1 (S2)** `createKey` (src/key.js): before writing, remove `<keyfile>.<pid>.<hex>.tmp`
  siblings whose pid is not this process and is dead (`process.kill(pid, 0)` throws `ESRCH`).
  `EPERM` or success means alive: leave the file. Removal errors are ignored. Test: a tmp named with
  the pid of an exited child process is removed; one named with a live pid is kept.
- **B2 (S1)** A failure writing the tmp file throws `cannot create key file <file>: <code>`; only
  `EEXIST` from `linkSync` means another process won. Test: tmp write fails with `EEXIST` → that
  error, not a later `ENOENT` read error.
- **B3 (S3)** `ensureOwnerOnly`: a `statSync` failure throws `cannot stat key file <file>: <code>`.
- **B4 (S4)** A missing `error.code` renders as `unknown error`, never `undefined` (chmod, create,
  read, stat messages).
- **B5 (V21)** `session.ttl` error no longer echoes the input:
  `session.ttl must look like 30m, 24h or 7d`.
- **B6 (V35)** `block()` (src/index.js): for `system` and `messages`, an array is emptied, a
  string becomes `""`, any other non-null value is replaced with `[]`.
- **B7 (V14)** `PlaceholderSession` requires `secret` to be a `Uint8Array` (Buffer included) of 32
  bytes; a 32-character string is rejected.

## C. Config, UX, docs

- **C1 (S11, S7)** `buildPatternSet` normalizes each exclude entry once: must be a string (else
  `patterns.exclude[i] must be a string`), trim, lowercase, strip a leading `*.`, then a leading
  `@`. Empty after that, or containing whitespace → `patterns.exclude[i] is empty or contains
  spaces`. Messages name the position, never the entry. `isExcluded` (src/engine.js) no longer
  lowercases entries per match; it relies on the normalized set from `buildPatternSet`.
  Normalization broadens two spellings slightly: `@x.com` also covers hosts under x.com, and

- **C2 (V18)** A non-string `patterns.builtin[i]` → `patterns.builtin[i] must be a string`.

## D. Performance

- **D1 (E5)** New `src/known.js`: `knownMatcher(needles)` sorts needles longest first and compiles
  them into regexes of at most `CHUNK = 200` alternatives each, instead of one alternation that
  falls off V8's fast path at roughly 600–1500 values. `replaceIn(text, placeholders, fn)`
  applies the chunks in order, each only to the gaps between placeholders, recomputed after every
  chunk, so a shorter needle never matches inside a placeholder an earlier chunk wrote.
  `find(text)` returns the first needle found or `null`. `knownPass` and step 3 of A1 use it with
  originals plus escaped forms.
- **D2 (V29)** `findLeak` (src/guard.js) builds one matcher over the known originals per call and
  uses `find` on each view, instead of `includes` per mapping per string. The category still comes
  from the placeholder.

Tests: 3000 known values containing `/` — every value replaced by `knownPass`, `findLeak` returns
`null`, and both finish within a time bound that the 0.2.3 code exceeds (measure the old code
first; pick the count and bound so the test is RED on 0.2.3). Chunk boundary: a value at position
CHUNK and one at CHUNK+1 are both replaced.
