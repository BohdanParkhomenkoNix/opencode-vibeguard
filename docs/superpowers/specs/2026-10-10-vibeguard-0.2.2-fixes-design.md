## Изменения

### 1. Страж видит вложенный JSON (`src/guard.js`)

`stringsOf` собирает строки тела запроса. Новое: если собранная строка после `trim()` начинается с `{` или `[` и разбирается `JSON.parse`, её строки тоже собираются, рекурсивно, до глубины 3 (тело запроса — уровень 0). Ошибка разбора — строка остаётся как есть, без исключения.

Зачем: `tool_calls[].function.arguments` — JSON-строка; секрет с `"`, `\` или управляющим символом остаётся экранированным после одного разбора и проходит мимо поиска известных значений.

Плейсхолдеры по-прежнему вырезаются перед проверкой каждой строки, поэтому замаскированное тело с вложенными плейсхолдерами проходит стража.

### 2. Атомарное создание ключа (`src/key.js`)

Если файла ключа нет:
1. создать каталог (`0700`);
2. записать 32 случайных байта во временный файл `<key>.<pid>.<hex8>.tmp` в том же каталоге, права `0600`, флаг `wx`;
3. `linkSync(tmp, key)`; `EEXIST` — ключ уже создал другой процесс, берётся его;
4. временный файл удаляется в любом случае (`finally`);
5. ключ читается.

Любая другая ошибка `link` (например, файловая система без жёстких ссылок) — исключение `cannot create key file <path>: <code>`; плагин блокирует запросы (fail-closed). Наполовину записанный ключ прочитать нельзя.

### 3. Права ключа (`src/key.js`)

После чтения ключа: если `statSync(key).mode & 0o077` ≠ 0, плагин молча делает `chmodSync(key, 0o600)`. Ошибка `chmod` — исключение `key file <path> is accessible by others and chmod failed: <code>`; запросы блокируются. Содержимое ключа в тексте ошибок не появляется.

### 4. `exclude` по домену (`src/engine.js`)

Совпадение исключается, если для какой-то записи `X` из `patterns.exclude` (сравнение без учёта регистра):
- совпадение равно `X`; или
- совпадение оканчивается на `@X` или на `.X`.

Примеры при `exclude: ["example.com"]`: `a@example.com`, `a@mail.example.com` — исключены; `a@notexample.com`, `example.com.evil.io` — нет.

Правило применяется ко всем видам правил (ключевые слова, regex, встроенные). Страж использует тот же `redactText`, поэтому маскировка и страж не расходятся. Следствие, описываемое в README: ключевое слово `boss@example.com` при `exclude: ["example.com"]` не маскируется.

### 5. `session.ttl: "0s"` — «никогда»

Поведение не меняется: `ttl` 0 означает, что сопоставления не истекают по времени (ограничение `max_mappings` действует). Это записывается в README и в JSDoc `PlaceholderSession`; добавляется unit-тест.

### 6. Версия

`package.json` `version` → `0.2.2`.

### 7. Глобальный конфиг (вне репозитория)

В `~/.config/opencode/vibeguard.config.json` правило `URL_CREDENTIALS`: квантификатор `{3,}` → `{8,}`. Остальное без изменений. Бэкап не делается (решение пользователя).

## Тесты

Unit, каждый сначала падает:
- страж: известное значение с `"` и `\` внутри `tool_calls[].function.arguments` → `findLeak` находит; замаскированное тело с плейсхолдерами во вложенном JSON → `null`; невалидный JSON, начинающийся с `{`, — без исключения; глубина больше 3 не разбирается;
- ключ: создание не оставляет `.tmp`; существующий ключ другого «процесса» (файл появился до `link`) берётся без перезаписи; права `0644` → после `loadKey` `0600`; ошибка `chmod` (`chmodSync` подменён) → исключение без байтов ключа;
- `exclude`: примеры из раздела 4, включая регистр (`A@Example.COM`);
- `ttl 0`: `cleanup` спустя большой срок ничего не удаляет.

E2E: весь набор `npm run test:e2e` зелёный.
