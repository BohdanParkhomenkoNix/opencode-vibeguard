# vibeguard для OpenCode V2: форк и порт (подпроект 2 из 3)

Дата: 2026-10-10. Подпроект 1: `2026-10-10-opencode-v2-core-migration-design.md`.

## Цель

Провайдер LLM не видит секреты из сессий OpenCode V2. Перед каждым запросом к модели секреты заменяются плейсхолдерами `__VG_<CATEGORY>_<hash12>__`. Перед запуском инструмента плейсхолдеры заменяются обратно, поэтому файлы и команды получают настоящие значения.

Основа — форк `inkdust2021/opencode-vibeguard` (MIT, 0.1.0, V1-only, без тестов). Он переносится на V2 plugin API.

Исходные факты:
- В V1 vibeguard был загружен, но ничего не делал: `vibeguard.config.json` нигде не было. Переход на V2 защиты не убавил. Этот подпроект впервые включает её по-настоящему.
- Спайк 2026-10-10 на V2 2.0.26:
  - хук `context` правит исходящие `system`/`messages`, а сохранённая история не меняется;
  - title-запрос идёт отдельно, его закрывает хук `title`;
  - `execute.before` подменяет аргументы инструмента, и файл получил настоящее значение;
  - тело запроса читается в `http.request` (`event.request` — `Request`, работает `clone().text()`);
  - хука для финального текста ответа нет.

## Вне рамок

- Восстановление настоящих значений в ответах на экране: ответы модели показывают плейсхолдеры.
- Совместимость с V1, PR в upstream, публикация в npm.
- Защита от кражи секрета через промпт-инъекцию: `bash` получает настоящие значения, значит `curl` может их отправить. Это ограничение подхода.
- Мутационное тестирование и архитектурное ревью плана.

## 2. Компоненты (подход A: ядро upstream, новая точка входа)

| Файл | Изменение | Ответственность |
|---|---|---|
| `src/index.js` | новый | `setup(ctx)`: регистрирует хуки (раздел 3); любая ошибка → отказ (раздел 4) |
| `src/key.js` | новый | HMAC-ключ: 32 случайных байта, файл с правами `0600`, создаётся при первом запуске. Путь берётся из `key_file` конфига, по умолчанию `~/.config/opencode/vibeguard.key`. Нечитаемый файл или неверная длина → ошибка |
| `src/messages.js` | новый | Обход V2-структур `system[]`, `messages[]` (`content[]` с частями) и чистка строковых значений. Служебные поля (`id`, `type`, `role`, `toolCallId`, `toolName`, `callID` и т. п.) не трогаются |
| `src/guard.js` | новый | Проверка тела исходящего запроса (раздел 3.3) |
| `src/session.js` | правка | Одно сопоставление на процесс (не на сессию); ключ из `key.js`; TTL и `max_mappings` как в upstream |
| `src/patterns.js` | правка | Новые встроенные правила: `openai_key` (`sk-…`, `sk-proj-…`), `anthropic_key` (`sk-ant-…`), `github_token` (`ghp_/gho_/ghu_/ghs_/ghr_/github_pat_…`), `aws_access_key` (`AKIA…`), `google_api_key` (`AIza…`), `private_key` (блок `-----BEGIN … PRIVATE KEY-----…-----END … PRIVATE KEY-----`), `jwt`. Правила upstream остаются |
| `src/config.js` | правка | Каталог проекта — `ctx.location.directory`. Новое поле `key_file`. Строгая проверка: битый regex, неизвестное правило или неверный тип поля → ошибка |
| `src/engine.js`, `deep.js`, `restore.js` | без изменений | Замена и восстановление |

Конфиг ищется как в upstream (первый найденный):
1. `OPENCODE_VIBEGUARD_CONFIG`;
2. `<проект>/vibeguard.config.json`;
3. `<проект>/.opencode/vibeguard.config.json`;
4. `~/.config/opencode/vibeguard.config.json`.

Нет конфига или `enabled: false` → плагин ничего не делает: так его выключают сознательно. Битый конфиг → отказ запросов, а не тихое выключение.

## 3. Поток данных

### 3.1 Перед запросом к модели

Хуки сессии `context`, `title`, `compaction`, `generate`:
1. Очистить TTL-просроченные сопоставления.
2. Пройти `event.system` и `event.messages` (`messages.js`) и заменить совпадения правил плейсхолдерами.
   - Сопоставления пополняются.
   - Вывод инструментов в истории хранится с настоящими значениями и чистится заново при каждом запросе.
   - После рестарта сервиса сопоставление восстанавливается при первом запросе, а постоянный ключ даёт те же плейсхолдеры.
3. Правки касаются только исходящего запроса.

### 3.2 Перед инструментом

`execute.before` для любого инструмента, кроме `websearch`: плейсхолдеры в `event.input` заменяются настоящими значениями (`restoreDeep`).
- Сопоставление общее, поэтому субагент (`task`) получает значения, которые спрятал родитель.
- В `websearch` плейсхолдеры остаются: секрет в поисковом запросе к сторонней службе не нужен никогда.
- После инструмента плагин ничего не делает.

### 3.3 Страж на выходе

`http.request`, для каждого исходящего запроса:
1. Прочитать тело (`request.clone().text()`) и разобрать JSON.
2. Пройти все строковые значения правилами (плейсхолдеры `__VG_…__` пропускаются) и проверить их на вхождение известных настоящих значений.
3. Любое совпадение → отказ запроса с ошибкой `vibeguard: plaintext <CATEGORY> in outgoing <kind> request`. Значение в ошибку и лог не пишется.
4. Тело не JSON → проверка того же на сыром тексте.

Страж ловит утечки из полей, которые пропустил обход: новые типы частей, новые виды запросов.

Описания инструментов (`tools`) не чистятся. Если совпадение найдётся там, запросы будут блокироваться, пока значение не добавлено в `exclude`. Ошибка называет категорию.

### 3.4 Плейсхолдер

Плейсхолдер — `__VG_<CATEGORY>_<hash12>__`, где `hash12` — первые 12 hex-символов `HMAC-SHA256(key, original)`. Формат как в upstream. При коллизии добавляется суффикс `_<N>`.

## 4. Fail-closed

- Ошибка в хуках раздела 3.1 или в страже (битый конфиг, нечитаемый ключ, исключение в замене) → `throw`, запрос не уходит.
- Ошибка в `execute.before` → `throw`, инструмент не запускается с плейсхолдером.
- Если в V2 `throw` в хуке не прерывает запрос (проверяется в Задаче 1 плана):
  - хук заменяет `system` и `messages` одной строкой `vibeguard: request blocked (<причина>)`;
  - страж отклоняет запрос.
- Если не прерывается и запрос из `http.request`, работа останавливается: поправка к спеке и согласование с пользователем.
- Лог: `console.error` с префиксом `[vibeguard]`, без значений секретов. При `debug: true` — строка на каждый запрос: `kind=<kind> replaced=<N> guard=clean`.

## 5. Глобальный конфиг

`~/.config/opencode/vibeguard.config.json`:
```json
{
  "enabled": true,
  "debug": false,
  "placeholder_prefix": "__VG_",
  "session": { "ttl": "24h", "max_mappings": 100000 },
  "patterns": {
    "keywords": [],
    "regex": [],
    "builtin": ["openai_key", "anthropic_key", "github_token", "aws_access_key", "google_api_key", "private_key", "jwt", "email"],
    "exclude": ["example.com", "localhost", "127.0.0.1", "0.0.0.0", "noreply@anthropic.com"]
  }
}
```
`uuid`, `ipv4`, `mac` и `china_*` выключены: они часто встречаются в коде, и замена мешала бы модели. Свои строки пользователь добавляет в `keywords`.

## 6. Тесты

### 6.1 Юнит-тесты

`node --test` в `test/unit/`; GitHub Actions гоняет их на каждый push:
- **patterns:** каждое новое правило ловит настоящие форматы и не ловит похожие строки; исключения работают.
- **engine:** цикл «спрятать → вернуть» даёт исходник; плейсхолдер стабилен с тем же ключом и отличается с другим.
- **key:**
  - создание с правами `0600` и 32 байтами;
  - повторное использование;
  - нечитаемый файл или неверная длина → ошибка.
- **config:**
  - порядок поиска;
  - `key_file`;
  - битый regex, неизвестное правило или неверный тип → ошибка;
  - нет конфига → выключен.
- **messages:** чистятся `system`, текст, рассуждения, аргументы и вывод инструментов; служебные поля не меняются.
- **session:** общее сопоставление между `sessionID`, TTL, `max_mappings`.
- **guard:**
  - чистое тело проходит;
  - секрет по правилу → ошибка;
  - известное значение с JSON-экранированием → ошибка;
  - не-JSON тело;
  - сообщение без значения секрета.
- **index** с фейковым `ctx`:
  - все хуки зарегистрированы;
  - `context`, `title` прячут;
  - `execute.before` возвращает значения везде, кроме `websearch`;
  - ошибки пробрасываются, а не глотаются.

### 6.2 E2E

`npm run test:e2e`, только локально. Настоящий бинарник `opencode` в режиме, не задевающем общий сервис пользователя (`--standalone` или эквивалент — Задача 1).

- **Мок-провайдер:** OpenAI-совместимый, отвечает потоково (SSE) по сценарию и записывает тела всех запросов.
- **Временный проект:**
  - `opencode.jsonc`: провайдер `local` (`package: "@opencode/ai/providers/openai-compatible"`, `settings.baseURL` на мок) и плагин по пути к клону;
  - `vibeguard.config.json` с тестовым `key_file` во временном каталоге;
  - `AGENTS.md` с секретом.

Сценарии:
1. Секрет в промпте, в `AGENTS.md` и в выводе `bash`. Ни одно записанное тело (основной запрос, title) не содержит секрета, плейсхолдер присутствует.
2. Мок отвечает вызовом `bash` с плейсхолдером. Файл на диске содержит настоящее значение.
3. Мок вызывает субагента. Его запросы чистые, его `bash` получает настоящее значение.
4. Compaction, вызванный маленьким лимитом контекста модели. Его запрос чистый.
5. Второй процесс продолжает ту же сессию. Плейсхолдер тот же, восстановление работает.
6. Битый конфиг. Мок не получает ни одного запроса, `opencode run` завершается ошибкой.
7. `websearch` с плейсхолдером. Аргумент остаётся плейсхолдером. Если вызвать `websearch` против мока нельзя, проверка остаётся на юнит-уровне (решение в Задаче 1).

### 6.3 Живая проверка

Один раз, после установки: временный проект, big-pickle, `debug: true`, секрет в промпте и в `bash`. В логе по каждому запросу `guard=clean`, файл получает настоящее значение.

## 7. Раскатка в OpenCode

1. Бэкап `~/.config/opencode/opencode.jsonc` (`.bak-2026-10-10-vibeguard`).
2. В `plugins` добавить `vibeguard@git+https://github.com/BohdanParkhomenkoNix/opencode-vibeguard.git`.
3. Создать `~/.config/opencode/vibeguard.config.json` (раздел 5). Ключ плагин создаст сам.
4. Перезапустить сервис из чистого окружения: `env -i HOME=… USER=… LOGNAME=… SHELL=/bin/zsh TERM=… zsh -lic 'opencode service restart'`.
5. `opencode plugin list`: `vibeguard` ровно один раз. Затем живая проверка (раздел 6.3).

Откат: вернуть `opencode.jsonc` из бэкапа и перезапустить сервис. Конфиг и ключ остаются, без записи в `plugins` они не действуют.

## 8. Критерии готовности

1. Юнит-тесты зелёные локально и в GitHub Actions на `main`.
2. E2E-сценарии 1–6 зелёные; сценарий 7 зелёный или закрыт на юнит-уровне с записью в ledger.
3. Факты Задачи 1 подтверждены, либо получена согласованная поправка к спеке:
   - `throw` прерывает запрос;
   - имя инструмента субагента;
   - compaction срабатывает;
   - изолированный запуск.
4. В OC `vibeguard` загружен ровно один раз, живая проверка прошла.
5. README форка описывает V2-установку, конфиг и ограничения (раздел «Вне рамок»).
